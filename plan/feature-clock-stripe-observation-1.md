# Bounded Stripe clock observation

Continue the approved trusted-publisher component from f10b096. This local adapter obtains the ready provider evidence needed by the existing preparators. It does not create, advance or delete a clock/Customer and has no CLI or secret resolver.

1. Expose the existing pure scope/fixture validation through a narrow shared context function. Preserve its DEV/TEST, two-binding, uniqueness and historical-owner rules; do not duplicate or relax them in the adapter.
2. Capture scope, selected owner, restricted test key, HTTP delegate, real clock and request budget before asynchronous work. Require explicit dependencies; do not use the default HTTP client or find keys in environment/SSM. Do not return or persist the key.
3. Execute once, serially: GET /v1/account and verify the expected Mexican account, GET the exact Customer and verify synthetic owner/stage/integration/test-clock membership, then GET its exact TestClock. No list, expand, connected-account header, POST, DELETE or alternate endpoint. Fix API to the application's Endive version. Require actual HTTP 200 responses.
4. At the HTTP-client seam, permit one delegation for each exact GET. Validate host/port/protocol/path/body/version/authentication before reserving budget. Prevent hidden connection-closed retries even though the installed SDK retries those independently of maxNetworkRetries=0. Bound duration and close the adapter after success/failure; a late SDK retry cannot obtain another delegation.
5. Normalize only the evidence fields the core needs, drop unrelated personal/provider fields, and validate the ready observation using the actual core. Advancing/failure/expired/crossed clocks do not produce publishable evidence. Return sanitized errors and reservation/delegation counts. A future separately bounded observation may be required while waiting for ready; do not silently poll or replay.
6. Add failing cases first; use the real Stripe SDK and an in-memory HttpClient, including hidden retry, budget failure, timeout, scope mismatch and data minimization. Run with the 271 retained cases and types. No physical API request, real key, file/journal/provider write, dependency, runtime or contract change.
